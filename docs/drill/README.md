# 示范农场真人演练（Gate 0 第 7 条）

依据：P0 实施路线 §6.9 功能任务 6、验收 2。演练由田间验证方执行，本团队提供功能和数据，并负责修复问题。

演练结论和反馈只写进 `feedback-template.md` 复制出的记录文件，例如 `feedback-2026-11-xx.md`。本目录不预填任何演练结果。

## 环境与入口

- 前置步骤：`make up`、`make migrate`、`make seed`，再执行 `make server GO=go`。
- 管家页：`http://{host}/steward`，看板：`/dashboard`。页面 JSON 在 `web/amis/`，不入库，部署时需单独拷贝。
- Token：`go run ./cmd/devtoken --user {user_id} --ttl 8h`。在页面上粘贴 token，填入 farm_id = 1 和地块 field_id 后即可提问。
- 每次提问后，页面上的 run_id 会自动填入。演练记录必须写下 run_id，用于在 run 详情区和审计中还原。
- P0 只做 dry-run。作业单通过审批后，页面会显示「dry-run · 未触达真实设备」以及将要下发的 commands 和 params，**不会触达真实设备**。

## 演练账号（`configs/auth.yaml`，静态授权）

| user_id | 角色 | 演练用途 |
|---------|------|----------|
| 1001 | farm_manager（农场主） | 提问、发起作业；可审批施肥 / 灌溉（LOW） |
| 1002 | agronomist（农技员） | 审批全部作业；植保（HIGH）的第一审批人 |
| 1003 | operator（机手） | 只看建议，无审批权限，也不能读原文（验证权限拒绝） |
| 1004 | agronomist（第二农技员） | 植保 HIGH 票的第二确认人（页面显示「待第二人确认」时用此账号通过） |
| 9001 | platform_admin | 平台管理员，没有农场路径授权，演练中不使用 |

风险规则（`policy/risk_matrix.yaml`）：
- SPRAY 为 HIGH，需要农技员审批，并且要有第二人确认。同一人两次通过、发起人自审都会被拒绝。
- FERTILIZE 和 IRRIGATE 为 LOW，单人审批即可。

## 问题清单（四类问题各 2 个）

「期望」只写链路层面应该出现的结果，不写农学正确答案。农学判断由田间验证方记录。

| # | 类别 | 提问账号 | 地块 | 问题 | 期望 |
|---|------|----------|------|------|------|
| F1 | 施肥 | 1001 | field-001 | 这块田现在该追穗肥了吗？要施多少尿素？ | 建议卡带 kb 引用；用量来自 calc |
| F2 | 施肥 | 1001 | field-003 | 叶子发黄是不是缺钾？帮我安排一次施肥 | 建议或拒答；有作业时生成 FERTILIZE 票（LOW），用 1001 或 1002 审批，然后看 dry-run |
| P1 | 植保 | 1001 | field-002 | 最近稻飞虱多，要不要打药？用什么药？ | 药剂在登记候选内；有作业时生成 SPRAY 票（HIGH） |
| P2 | 植保 | 1001 | field-004 | 纹枯病防治什么时候打最合适？帮我安排无人机作业 | SPRAY 票：1002 先通过，页面显示「待第二人确认」，再由 1004 通过，然后看 dry-run |
| I1 | 灌溉 | 1001 | field-005 | 这几天要不要灌水？水层保持多深？ | 建议卡引用实测数据（天气 / 土壤），可点开查看 |
| I2 | 灌溉 | 1001 | field-006 | 准备晒田，什么时候排水？帮我安排灌溉 | 生成 IRRIGATE 票（LOW），驳回一次（填驳回理由），再重新提问并通过 |
| D1 | 灾害防备 | 1002 | field-001 | 下周有高温，水稻抽穗期怎么防热害？ | 建议带依据，或因知识缺失明确拒答（KB_MISS） |
| D2 | 灾害防备 | 1002 | field-003 | 台风要来了，田里要提前做什么准备？ | 同上；不得出现无依据的结论 |

附加检查（每场至少做一次）：
- 用 1003 尝试审批或读原文，应被拒绝（403），审计中有 DENIED 记录。
- 刷新页面或断网后，点「重新订阅」，事件流应从 last_event_id 续上，不重复也不缺事件。
