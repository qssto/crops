# 场景说明书（P0 · L0 场景冻结）

> 状态：**Claude 草拟，待业务与农艺书面确认**（P0 §6.1 验收 1）。确认前本页内容只作为 L0–L3 开发占位，不作为对外承诺。
> 版本：v0.1 草稿，2026-10-28

## 1. 场景（D2 占位）

| 项 | 取值 |
|----|------|
| 作物 | 水稻（单季稻，P0 不区分早 / 中 / 晚稻品种差异） |
| 区域 | 江苏 |
| 示范农场 | 示范农场1（`tenant_id=1, farm_id=1`；评测样本中合成编码为 `farm-demo-01`，地块 `field-001`–`field-006`） |
| 交互方式 | 内部 Web 页对话（L8）；设备动作只生成作业单草稿并转审批，只做 dry-run |

## 2. 目标用户角色

| 角色 code | 角色 | 典型诉求 | P0 能做的事 |
|-----------|------|----------|-------------|
| `farm_manager` | 农场主 | 「这块田要不要打药 / 施肥 / 灌水」「帮我安排作业」 | 提问、查看建议、发起作业（停在待审批） |
| `agronomist` | 农艺师 | 病虫害判断、药剂与用量核对、审批作业单 | 提问、审批（P0 身份与角色为静态配置，见 L1） |
| `operator` | 机手 | 作业参数（亩用量、兑水量、灌水量）、作业时间窗 | 提问、查看 dry-run 结果 |

## 3. 问题域（四类，子类见 `eval/taxonomy.yaml`）

1. 施肥 `fertilize`：施肥时机、肥料选择、用量计算、缺素诊断。
2. 植保 `protect`：病虫害识别、防治时机、药剂选择、用量计算。
3. 灌溉 `irrigate`：灌溉时机、水层管理、晒田与排水、用水量计算。
4. 灾害防备 `disaster`：高温热害、低温冷害、台风暴雨、倒伏。

## 4. 红线（不可让步）

1. 无依据不下结论：每条建议都带 `Citation`（知识条目 `kb_id@version` 或工具实测数据）；知识未覆盖（`KB_MISS`）或关键数据缺失时明确拒答，不回落到模型记忆。
2. 数值与药剂不出自模型：用量、稀释倍数、安全间隔、施肥量一律由 `calc` 规则层计算；药剂只能在农药登记候选集合内选择。
3. 模型不直接动设备：涉及设备动作的请求 100% 停在审批，审批前设备 Adapter 零调用；P0 只 dry-run。
4. 隐私不出域：日志与模型输入中无手机号、身份证、精确坐标明文。

## 5. 范围外（P0 一律拒答或不做）

1. 水稻以外的作物、江苏以外的区域、示范农场1以外的农场（`OUT_OF_SCOPE`）。
2. 知识库未覆盖的主题：功能性栽培（富硒等）、灾损定损与保险理赔、农产品价格与销售、政策补贴（`KB_MISS`）。
3. 图片诊断、主动预警推送、多机协同排程、真实设备下发（Phase 1+）。
4. 未登记于水稻的药剂、超登记剂量的用法。
