# 回执映射表

依据：P1 手册 §6.3 功能任务 2。代码常量：`internal/model/receipt.go` 的 `ReceiptRules` / `MapReceipt`，全表测试 `TestMapReceipt_FullTable`；改表须同时改这三处。

本层（L2）只给出映射，不改 work_order 状态机；迁移由 L4 下发器消费 `ReceiptRule.Effect` / `ReceiptRule.To` 执行。

## 标准回执

各 Adapter 把自家协议转成 `model.DeviceReceipt`，下发器只认它：

| 字段 | 说明 |
|------|------|
| `Status` | `ACCEPTED / EXECUTING / DONE / FAILED / CANCELED / PARTIALLY_DONE`；`SENT / NO_RECEIPT` 是本地态，设备不会回 |
| `DeviceJobID` | 平台任务号；除 FAILED（可能未受理）外必填 |
| `DoneAreaMu` | 已完成面积（亩），`>= 0`；PARTIALLY_DONE 必须 `> 0` |
| `DeviceTime` | 设备 / 平台侧时间（UTC），零值表示平台未给 |
| `FailureKind` | 仅 FAILED，必填：`NOT_EXECUTED / IN_EXECUTION / UNKNOWN` |
| `Code` | 平台回执码，原样进 trace |

不满足以上约束的回执由 `DeviceReceipt.Validate` 返回 `model.ErrBadReceipt`。

## 回执 → WorkOrder 迁移事件

| dispatch_attempt.status | failure_kind | done_area_mu | 处置（Effect） | 作业单迁移到 |
|-------------------------|--------------|--------------|----------------|--------------|
| SENT | — | — | NONE：只更新 dispatch_attempt | — |
| ACCEPTED | — | — | NONE | — |
| EXECUTING | — | — | TRANSITION | EXECUTING |
| DONE | — | — | TRANSITION | DONE |
| PARTIALLY_DONE | — | > 0 | TRANSITION | PARTIALLY_DONE |
| CANCELED | — | 空或 0 | TRANSITION | CANCELED |
| CANCELED | — | > 0 | TRANSITION：撤销前已部分喷施，安全间隔期与重复作业判断必须计入（安全优先） | PARTIALLY_DONE |
| FAILED | IN_EXECUTION | — | TRANSITION | FAILED |
| FAILED | NOT_EXECUTED | — | RETRY_OR_FAIL：attempt+1 重试，末次失败 | FAILED（末次） |
| FAILED | UNKNOWN | — | RECONCILE：不迁移，进待对账列表，人工处理 | — |
| NO_RECEIPT | — | — | RECONCILE | — |

查表入口 `MapReceipt(status, failure_kind, done_area_mu)`：非 FAILED 忽略 failure_kind，非 CANCELED 忽略 done_area_mu。表外组合（如 FAILED 缺 failure_kind）返回 `ErrBadReceipt`。待对账列表即 `DispatchAttemptRepo.PendingReconcile`：`status='NO_RECEIPT' OR (status='FAILED' AND failure_kind='UNKNOWN')`。

写库前校验：`DispatchAttemptRepo.SetJobTx` 校验整张回执（`DeviceReceipt.Validate`），`UpdateReceiptTx` 校验 `model.CheckAttemptState`（status 已登记、FAILED 必带 failure_kind 且其余状态不得带、面积 `>= 0`），不合规返回 `ErrBadReceipt` 且不写库；`done_area_mu` 传 nil 时保留库里旧值（`COALESCE`）。

## devicesim 协议 → 标准回执

实现：`internal/adapter/devicesim/client.go` 的 `stateMap` / `stageMap`；端到端测试 `internal/adapter/devicesim/devicesim_test.go`。

| devicesim `state` | 标准 Status |
|-------------------|-------------|
| accepted | ACCEPTED |
| running | EXECUTING |
| finished | DONE |
| partial | PARTIALLY_DONE |
| failed | FAILED |
| canceled | CANCELED |

| devicesim `fail_stage` | FailureKind |
|------------------------|-------------|
| before_start | NOT_EXECUTED |
| in_progress | IN_EXECUTION |
| unknown | UNKNOWN |

未登记的 state / fail_stage、自相矛盾的回执一律 `adapter.ErrBadReceipt`。

## 调用错误归类（devicesim 客户端）

| 情况 | 错误 |
|------|------|
| 请求超时 | `adapter.ErrTimeout` |
| 2xx 响应头之后读 body 失败 | `adapter.ErrTimeout`（平台可能已受理，结果未知，按 idem_key 查询 / 对账） |
| 连接失败 / HTTP 5xx / 非 2xx 读 body 失败 | `adapter.ErrUnavailable` |
| HTTP 404 | `adapter.ErrJobNotFound` |
| 其余 4xx | `adapter.ErrRejected` |
| 响应不是合法回执 / 2xx body 超过 1 MiB | `adapter.ErrBadReceipt` |
| 返回任务的 job_id / external_no / order_id 与请求不一致 | `adapter.ErrBadReceipt`（防平台串单） |

下发超时（未拿到 device_job_id）的后续处置：按 idem_key 走 `QueryStatus`（需平台声明 `ExternalQuery`），仍无结果记 NO_RECEIPT 进待对账。L4 接入。
