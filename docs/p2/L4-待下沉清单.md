## 1. 盘点口径

路线要求用 Phase 0-1 线上 `run_id` 回放与驳回原因（时机不对 / 药剂不对 / 用量不对）定位模型隐式承担的确定性判断。本仓库没有线上 run，也没有审批驳回记录，本次改用两类证据：

1. **regression / capability 样本的问题文本**：问题里出现了需要确定性判断的情形（下雨能不能打、两种药能否一桶混、几种虫同时发生先治哪个）。
2. **P1 基线评测 transcript**：`baseline_p1` = exp 102（stub 模型，regression + redteam，n=5，850/850 PASS）。每个 trial 用独立库，`run_id` 都是 1，transcript 位于 `eval/out/transcript/102/{sample_id}/{trial}.jsonl`（主仓 `eval/out/`，不入库）。stub 模型的 explain 输出是固定模板，只能证明链路上「这段判断交给了模型原文」，证明不了真实模型会出错。

全部条目标 **待线上数据**：线上有 run 后，按驳回原因 `TIMING / PRODUCT` 回查 `approval_rejection` 与对应 `run_id`，补进本表。

三项的共同行为如下：

- 拒收在 off / shadow / on 下都生效，也不受农场覆盖影响：`output_validator` 不读开关，graph 每轮都把 `RuleOutputs` 传给它。
- shadow 时不注入。模型输出后，用拒收同一实现 `guardrail.CheckRules` 做比对，比对行与建议卡在同一事务写入 `rule_shadow_diff`：冲突行 `agreed=0` 带掩码分句，拒答时 `advice_id=0`。落库后发 `RULE_SHADOW_DIFF` 事件。
- 开关读失败或未装配时按 off 处理。
- 开关全关时，explain 入参与 P1 逐字节相同（`constraints` 字段 omitempty），落卡走原来的 `SaveAdvice`。

## 3. 覆盖检查（路线功能任务 3 / 验收 3）

核查问题：Phase 0 已由规则层承担的三项（生育期、PHI、`product_candidates`），是否还有路径让模型绕过，例如解释文本里出现规则层没给出的时间或药剂。发现的绕过一律先写应失败测试再修，修复提交为 `bd2d620`。

| 项 | 核查路径 | 结论 | 测试 |
|---|---|---|---|
| 生育期 | 施肥类的时期（基肥 / 分蘖肥 / 穗肥）取自分类槽位，槽位由模型从问题里抽取。物候工具给出的当前生育期不在该时期条目的适用期内时，条目阈值全部「不适用」，被当成满足，规则层给出作业类结论 | **有绕过，已修**：`rules_fertilize.go` 的 `decideFertStage` 加 `stageApplies` 否决，生育期不符时只给观察类、不出作业单，用量照算 | `graph.TestAgentAsk_FertStageFollowsPhenology`（修复前失败） |
| PHI | 问题没提收获，但预计收获日已在所选药剂安全间隔期内 | **无绕过**：规则层按 P1 L3 设计不过滤候选，由 to_order 开票前约束闸门 `phi_interval` 拦截，工单留 DRAFT、不开票；拦截与问题措辞无关。没有在规则层重复过滤，因为那会改变红线样本 rice-cons-0012 / 0014 / 0040 的期望 | `graph.TestAgentAsk_PHIWithoutHarvestWords`（固定该路径） |
| `product_candidates` | 护栏只校验卡片的 `selected_product`，模型结论 / 理由原文里写的药名（如「建议改用毒死蜱」）不受约束 | **有绕过，已修**：`output_validator` 新增原文药名校验 `ProductMentions`：规则层给出候选时，原文推荐的药剂须在候选内，否则 `VALIDATION_FAILED`（check=`product`），常开；否定句与历史回显不计 | `guardrail.TestValidate_ProductMentionOutsideCandidates`、`graph.TestAgentAsk_ProductMentionOutsideCandidates`（修复前失败） |

时间方面，「规则层没给出的作业时间」由本批的作业窗口拒收覆盖（§2 第一行）。窗口未判定任何硬约束时（没调用天气工具）不拒收，`TestValidate_WindowNotEvaluatedSkips` 固定了这一行为。
