# P1 第 2 批简报：L2 ∥ L3（两个子 agent 并行）

先读：`docs/agent-brief-common.md`、`docs/briefs/P1-common.md`（环境 / 命名空间 / 提交规则）、`docs/dev-log.md` 的 P1-L0 / P1-L1-A / P1-L1-B 小节（开关、权限、Scope、SystemScope 的现状与偏差）。
基线分支：`p1-l2l3-base`（= p1-l1-merge 68ce3ca + 本简报）。开工先 `git merge --ff-only p1-l2l3-base`。
命名空间：L2 用 `AS_TEST_NS=l2`，L3 用 `AS_TEST_NS=l3`。

## 已定决策（调度方与用户已确认，不要改）
- 无 D4 设备协议：L2 新建本地设备模拟平台 `cmd/devicesim` 与对接它的 Adapter；四类真实设备（植保 P 系列 / 车辆 R·RM / 阀门 FBV·FGV / 智能施肥 FPDI·FPI）只留骨架，在注册表中标「不可开放」。
- 下发器（`service/workorder_dispatch.go`）接入真实 Adapter、`dispatch_attempt` 写入、回执消费、复检退回（`ApprovalService.Reopen`）都在 **L4**。§7.2-2 要求复检退回 / 下发器 / Reopen 同一提交，所以 L3 **不做** PRE_DISPATCH 不通过后的退回，也不做「审批后恶化天气」打分器。
- 不新增第三方依赖（devicesim 用标准库 `net/http`）。

## 迁移编号
- L2：`0007_dispatch_attempt`（§6.3 SQL 照抄）；L3：`0008_order_field_status`（§6.4 的 `ALTER TABLE work_order ADD KEY idx_field_status`）。

## L2 / L3 之间的接缝（只加不改）
- `mcp-device` 现有 `device.status` 输出字段（`online / state / battery_pct / tank_l / last_seen_at / data_freshness_sec / source` 等）L2 只能加字段，不能改名或删除；L3 的续航载药 checker 只读这些字段。
- 设备规格（药箱容量、满电可作业亩数等）放知识库阈值（L3 负责，见 L3 第 1 条），不放 `configs/mock/device.yaml`。

## 共享文件（会冲突，只做追加、各写各的函数 / 段落 / 新文件，调度方合并）
- `internal/app/*`：L2 装配 Registry / devicesim Adapter / mcp-device real；L3 装配 checker 注册表、LocalOrderSource、法规映射。尽量各开新文件。
- `internal/evalkit/*`（样本结构、fixture、打分器注册）：L2 加「设备回执序列」字段与 RecordingAdapter 三方法；L3 加约束样本组需要的字段（如预置本地工单）与约束打分器。字段只加不改，样本校验对新字段宽松（缺省 = 旧行为），保证现有 114 条样本不改也能过 validate。
- `internal/model/*`：各开新文件（如 `model/device.go`、`model/constraint.go`），不改现有类型的已有字段。
- `internal/archtest/rules.go`：各自追加规则，写清楚理由。
- `docs/dev-log.md`：各写各的小节（`## P1-L2 …` / `## P1-L3 …`）。

## L2（1 人）：设备 Adapter 三方法、Registry 启动自检、本地设备模拟平台 —— P1 手册 §6.3（258-327 行）
文件归属：`internal/adapter/**`、`cmd/devicesim/`、`internal/agent/tools/mcp/servers/device/`、`configs/mock/device.yaml`、mcp 配置（`configs/tools.yaml` 或新建的 mcp 配置文件）、`migrations/0007_*`、`internal/repository/dispatch_attempt.go`、`internal/repository/rediskey`（加 `idem:dispatch` 键）、`internal/evalkit/env/adapter.go`、`docs/p1/`（回执映射表、设备开放清单更新）、`Makefile`（如需 `devicesim` 目标）。
1. `adapter.DeviceAdapter` 改为三方法 `Dispatch(ctx, order, idemKey) / QueryStatus(ctx, ref) / Cancel(ctx, deviceJobID)`，`ref` 可按 `idem_key` 或 `device_job_id` 查。`DryRun` 保留（P0 dry-run 下发仍用，可拆成单独小接口，按 ISP 自行决定，调用方跟着改）。入参是 `work_order.payload` 的设备无关表示，各 Adapter 自己转协议。Adapter 不 import `repository`、不注册为模型工具（archtest 加规则）。
2. 回执标准化：定义 `ACCEPTED / EXECUTING / DONE / FAILED / CANCELED / PARTIALLY_DONE`（另有本地态 `SENT / NO_RECEIPT`，与 `dispatch_attempt.status` 一致）+ `done_area_mu` + 设备时间 + `failure_kind`（`NOT_EXECUTED / IN_EXECUTION / UNKNOWN`）。给出「回执 → WorkOrder 迁移事件」映射表（代码常量 + `docs/p1/回执映射表.md`），L4 消费，本层不改 work_order 状态机。
3. `adapter.Registry`：按 `work_order.device_type` 注册；每个 Adapter 声明能力 `Cancel / IdemKey / ExternalQuery`。未实现 Cancel、或 IdemKey 与 ExternalQuery 都不支持的类型 **Register 返回错误**；app 启动时任一注册失败即启动失败（启动自检）。提供 `Openable(deviceType) bool`；四类真实设备骨架注册为「不可开放」（不进可开放集合，调用返回明确错误如 `ErrDeviceNotOpen`）。`to_order` 写 `dispatch_mode` 时：`enable_robot_dispatch` 开 **且** `Registry.Openable(device_type)` 才写 `REAL`，否则 `DRY_RUN`（改 app 里组装 `agent.DispatchModeSource` 的那一处，L0 的 FlagService 不动）。
4. `cmd/devicesim`：本地 HTTP 设备平台（只用于本地 / 预发演练，配置里显式开启）。支持：按 idem_key 幂等受理（同键重复提交返回同一 job）、按 job_id 或外部单号查状态、cancel、可脚本化的回执序列（成功 / 失败 / 部分完成 / 无回执 / 延迟）。对接它的 Adapter 放 `internal/adapter/devicesim`（HTTP 客户端，超时可配，地址来自配置）。端到端测试：起 devicesim（`httptest` 即可）跑 `Dispatch → QueryStatus → Cancel`，结果与映射表一致（验收 1）。
5. `dispatch_attempt`：迁移 + `repository.DispatchAttemptRepo`（插入 SENT、按 row_ver 更新回执 / device_job_id、按 Scope 查待对账列表；`uk_job` 反查只走 `SystemScope`，与 L1-B 规则一致）+ 集成测试（唯一键冲突、row_ver 冲突）。Redis 键 `idem:dispatch:{order_id}:{ticket_id}:{attempt}` 7d 经 `rediskey` 拼。**本层不改下发器**。
6. trace 与指令原文：做一个 Adapter 装饰器（如 `adapter.Traced`），每次调用记录 `tool_call_id / device_type / order_id / 耗时 / 回执码`，指令原文经 `RawStore.Put(kind=DEVICE_CMD)` 写入（key 按母文档 §4.6.2-8）。装饰器依赖的记录接口定义在 adapter 包，实现放 service（或复用现有 ToolCallStore / RawStore），集成测试证明可按 `run_id` 从 raw_store 取回原文（验收 4）。下发器接入在 L4。
7. `mcp-device` real：实现从 devicesim 取在线 / 续航 / 载药 / 能力，带 `data_freshness_sec` 与 `source`；mock / real 只由配置切换，业务代码零改动（测试：同一调用方代码在两种配置下都能跑）。eval 与集成测试默认仍 mock。
8. 评测：`env.RecordingAdapter` 记录三方法（`MethodQueryStatus / MethodCancel`）；样本可声明设备回执序列（成功、失败、部分完成、无回执），RecordingAdapter 按序列返回。现有 `no_model_actuate`、`cross_farm_isolation` 打分器照旧可用。
9. 测试（红线：下发路径）：Registry 自检表驱动（缺 Cancel / 无 IdemKey 且无 ExternalQuery → 注册失败，骨架 → 不可开放，`to_order` 开关开但类型不可开放 → DRY_RUN）；devicesim 幂等重复受理；回执映射全表；Adapter 超时 / 5xx / 非法回执的错误路径。
10. 文档：`docs/p1/` 下《设备开放清单》更新 devicesim 一行与骨架状态；验收 1（预发沙箱演练）标「待演练」，本地 devicesim 结果作为材料。
11. 验收 §6.3 1-5 逐条回报；第 5 条（`no_model_actuate` regression 全过）可带 `AS_TEST_NS=l2` 跑 `make eval GO=go N=3` 自查；被权限拒绝就如实回报，不要绕过。

## L3（1 人）：constraint_checker 注册表、审批前拦截、法规映射 —— P1 手册 §6.4（329-399 行）功能任务 1、2、4、5、6、7（不含复检退回与其打分器）
文件归属：`internal/agent/guardrail/constraint/`（新包）、`internal/agent/graph/constraint.go` 与 `assemble.go` 中产出 ConstraintChecks 的部分、`internal/agent/graph/recheck.go` 中 checks 的产出、`internal/agent/calc`（PHI 如需补）、`internal/service/approval.go` 的 `Open`、`internal/repository/` 新的 LocalOrderSource 实现文件、`migrations/0008_*`、`knowledge/common/*`、`policy/regulation_map.yaml`、`internal/agent/tools/mcp/servers/field/` 与 `weather/`（补边界 / 禁飞区 / 相邻地块 / 风向）、`configs/mock/field.yaml`、`configs/mock/weather.yaml`、`eval/suites/constraint/`、evalkit 约束打分器、`docs/p1/法规对照表.md`。
1. `constraint.Checker` 接口 + 注册表，每项一个实现：风速、降雨、温度、PHI、重复作业、禁飞与敏感区、续航载药、相邻地块飘移。统一输出对应 P0 `constraint_check` 列（`rule_id / passed / observed{value, unit, source, collected_at, tool_call_id} / threshold{value, unit, kb@version}`），沿用 `graph/constraint.go` 里现有的 observed / threshold 结构与 rule_id 长度规则。阈值全部从 `knowledge/common/*.md`（或 `pesticide_registry.yaml`）按 `kb_id@version` 读，不硬编码；缺的阈值（禁飞区边界规则、药箱容量与满电亩数、飘移敏感性）补进知识条目，`review_status: pending_expert`，标「待农艺专家签字」。禁飞区边界判定写明是否含边界。checker 只吃已取到的数据（工具结果 / 本地工单），不自己发 IO。
2. 数据缺失、过期（超过知识里的 `data_freshness` 阈值）或无 `tool_call_id` 来源，一律 `passed=false`（现有实现是「跳过不写」，改为写一条不通过）。注册表外的约束项不生效；同一工单类型必须跑到的 checker 集合由注册表决定，缺项按不通过。
3. `agent.LocalOrderSource`（定义在 `internal/agent`，repository 实现、app 注入）：§6.4 那条本地工单 SQL 照抄（只取 `dispatch_mode='REAL'`），与 `field.history` 取并集按 `order_id` 去重，供 PHI 与重复作业使用。迁移 0008 加 `idx_field_status`。
4. 审批前拦截（红线：审批闸门）：`ApprovalService.Open` 由提示改为拦截。顺序：法规前置条件 → 约束结果；任一不通过（含 `regulation_map.yaml` 中 `unmapped` 条目）则同事务只写 `constraint_check(PRE_APPROVAL, attempt=1)`（即 ticket_seq），**不建票、不迁移**，工单留 `DRAFT`，返回统一错误（如 `agent.ErrConstraintBlocked`，错误码 `CONSTRAINT_BLOCKED`）。graph 收到后让 run 正常收尾并在 outcome / 事件里带出被拦的 rule_id（审批页 / run 详情可见，验收 5）。重复开票、已建票的幂等行为不变。Open 只信任落库前重新校验过的 checks（防御：checks 为空或缺注册表要求的 rule_id 也拦）。
5. PRE_DISPATCH：`graph/recheck.go` 产出的 checks 改走同一注册表（实时数据重取由现有 epoch 机制保证），本层照旧只记录、不拦截，不通过后的退回在 L4。
6. 法规映射：`policy/regulation_map.yaml`，条目来自 `docs/p1/` 的《法规清单初稿》，每条映射为 `checker`（指 rule_id）/ `precondition`（如操控员资质登记、飞防药剂登记信息）/ `unmapped`（按不通过）；启动时校验引用的 rule_id 已注册。产出「法规条目 → 规则 / 前置条件 → 代码位置」对照表 `docs/p1/法规对照表.md`（法务签字栏标「待签字」）。`cmd/auditctl reg-report` 若工作量可控就做（生成同一张表），否则写明留给 L7 并回报。
7. 评测：`eval/suites/constraint/`，每类约束各一组（正常、超阈值、边界值、数据缺失），PHI 差 1 天、禁飞区边界、相邻地块飘移、本地已有在途同类工单（`field.history` 为空）各单列；打分器判定拦截（`CONSTRAINT_BLOCKED` + 对应 rule_id、无票据、工单 DRAFT、无设备调用）。样本要能过 `cmd/eval validate`；让 `make eval SUITE=constraint` 可跑。现有 regression 结论不能因为拦截而翻转（如有样本因新拦截改变结果，逐条回报原因）。
8. 测试：每个 checker 表驱动单测（含边界值、数据缺失按不通过、过期按不通过）；Open 拦截的应失败用例（不通过 → 无票无迁移、checks 已写）；LocalOrderSource 集成测试（DRY_RUN 单不参与、PHI 窗口边界）。
9. 验收 §6.4：1、2、4、5 逐条回报；3（审批后改天气退回）写「L4 交付」；4 的法务签字写「待签字」。第 1 条可带 `AS_TEST_NS=l3` 跑 `make eval GO=go SUITE=constraint N=3` 自查；被权限拒绝就如实回报，不要绕过。
