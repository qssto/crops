## L7-A（红线：审计不可篡改、导出脱敏）：哈希链、每日锚点、auditctl、审计导出、敏感操作二次留痕、保留期 —— §6.8 功能任务 3-6；技术实现第 1-5、7 条
文件归属：`migrations/0011_audit_chain.*`、`internal/repository/audit.go` 与新的 `repository/audit_chain.go`（封链、校验读取）、`repository/aftercommit.go` 的 `inTx`（提交前封链钩子）、新的 `internal/service/audit_*.go`（锚点、导出、保留期任务）、新命令 `cmd/auditctl`、`cmd/migrate`（`(0,0)` head 预建、锚点 bucket 建桶、`expire_at` 回填）、`internal/seed`（农场开通预建 head）、`repository/rawstore.go`（登记 `expire_at`）、新的 `controller/audit_export.go`、敏感操作调用点（开关变更、审批决策、中止作业、读 raw、导出）。
1. 哈希链（技术实现第 1 条，定版）：审计写入统一封链。`AppendTx` 只把条目挂到事务上下文，`inTx` 在提交前统一封链：按 `(tenant_id, farm_id)` 升序 `SELECT … FOR UPDATE` 涉及的 `audit_chain_head` → 逐条 `chain_seq = head+1`、`row_hash = sha256(prev_hash || canonical_json(行))` → `INSERT audit_log` → 推进 head。`Append`（独立短写，拒绝类审计）自开短事务走同一封链。核对所有写 `audit_log` 的入口都经这两条路径（含不经 `inTx` 开启的事务：要么改走 `inTx`，要么在 `AppendTx` 里检测到没有封链钩子时报错，不得写出无链行）。head 行缺失（未预建）→ 审计写失败、业务回滚。封链失败触发 `AlertSink`（审计写失败，P0）。
2. 哈希确定性（重点，必须有测试）：参与哈希的字段不含自增 `id`；时间截到毫秒 UTC；`summary` 是 MySQL JSON 列，读回时键序与空白会被 MySQL 改写，所以哈希一律对「规范化后的 JSON」计算，校验时把读回的 `summary` 再规范化后重算。数字（含浮点）与 `null` / 缺省列的处理写清并测试；集成测试：写入 → 读回 → 重算一致，覆盖含中文、浮点、嵌套对象的 summary。
3. 每日锚点（技术实现第 3 条）：worker 任务 `audit_anchor`（`lock:scan:audit_anchor`，每日 00:10，扫描周期内判定当日是否已锚定，幂等）读全部 `audit_chain_head` 写 `agri-steward-audit-anchor` bucket 的 `anchor/{yyyymmdd}.json`（各链 `chain_seq / head_hash` + 整体 sha256），再 `verify` 前一日增量；失败 → `AlertSink`（链断，P0）。bucket 由 `cmd/migrate up` 创建并开启 object lock（COMPLIANCE，天数取配置）；本机 MinIO 不支持 object lock 时建桶报错要清楚，测试里可用普通 bucket 并注明。全关（§8.3 第 4 条）只写进告警清单的处置，不在代码里自动关开关。
4. `cmd/auditctl`（技术实现第 4 条）：`verify --farm <id> [--tenant] [--from-seq --to-seq]` 流式按 `chain_seq` 重算，报第一个 `ROW_MODIFIED / GAP / LINK_BROKEN`（带 chain_seq 与 audit_log.id），退出码非 0；`anchor-check --date` 比对锚点与当前链，发现「截尾后重算整条链」；预留 `--from-manifest`（只解析参数、返回未启用）。只读连接、密钥同其他命令从环境变量 / deploy/.env 读，不打印。历史 `chain_seq IS NULL` 行跳过，从首个非 NULL 行开始。验收 2：集成测试篡改一行 summary / 删一行 / 改 prev_hash，分别定位到 `ROW_MODIFIED / GAP / LINK_BROKEN`。
5. 审计导出（技术实现第 5 条，定版）：`POST /api/v1/farms/{farm_id}/audit/exports`（权限 `audit.export` 只给 `auditor / platform_admin`，登记进权限矩阵与 archtest；路径 `farm_id` 不在 Scope → 拒绝并写 CROSS_FARM_DENIED）只写 outbox `audit.export`，返回 `export_id`；worker 处理器：只读该农场链区间 → 先 verify（失败置 FAILED + 告警，不导出）→ 逐行 `pii_mask` → zip 经 `RawStore.Put`（`kind=EXPORT`、`run_id` 段为 0）→ `raw_object_id` 回写 payload → `pii_clean` 扫描出口文件，命中则删对象、置 FAILED、告警。`GET …/audit/exports/{export_id}` 按 `tenant_id, farm_id, id` 查 outbox（他场即 404）返回进度与 5 分钟预签名 URL，下载写 `SENSITIVE.RAW_READ`。导出区间上限可配（默认 31 天）。
6. 敏感操作二次留痕（技术实现第 2 条）：开关变更、审批决策（APPROVE / CONFIRM / REJECT）、中止作业、读 `raw_object`、导出审计五类，在主审计同事务再写 `audit_log(action='SENSITIVE.{op}', target=主记录 id)`，动作名登记到 `model/audit.go`。验收 5：五类各一条集成测试断言两行同事务（主事务回滚两行都没有）。
7. 保留期（技术实现第 7 条）：`retention` 配置段按 `raw_object.kind` 与表名声明天数（缺 kind 启动失败）；`RawStore.Put` 写 `expire_at`；worker 任务 `retention`（`lock:scan:retention`，每日）按 §6.8 SQL 分批：先删 MinIO 对象再置 `deleted_at`，每批一条 `RETENTION_PURGE` 审计；仍被未终态工单 / 未关闭票据引用的对象跳过；`audit_log` / `run_event` 只登记不删。读 raw 遇 `deleted_at` 非空返回「原文已过保留期」的明确错误。
8. 测试（红线，必须有应失败用例）：规范化表驱动；封链加锁顺序（同一事务写农场链与 `(0,0)` 链，两个并发事务交叉写不死锁，`-race`）；head 缺失回滚业务；三类篡改定位；导出跨农场 404、权限拒绝、`pii_clean` 命中删除对象；保留期跳过被引用对象。评测 trial 库与种子要预建 head，`cmd/eval` 集成测试与现有样本不得因封链失败。
9. 验收 §6.8 第 2、3、5 条逐条回报（第 3 条「抽查 100 单」写成可复现的 SQL / auditctl 命令，结果标「待演练」）。
