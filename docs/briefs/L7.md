## 分工与文件归属（各自 worktree，互不改对方文件）

### L7-A（写路径：审计、回调、raw 读取、分区）—— 功能任务 1、2、3、7，验收 2、3、5
- `repository.EventRepo.AppendTx`：同事务按 `EventType.AuditAction()` 写 `audit_log` 投影（actor_type / actor_id / action / target（如 `tool:weather.forecast`、`order:12`、`ticket:7`）/ payload_digest = sha256(payload) / summary = payload（已脱敏，≤8KB）/ result（VALIDATION_FAILED → FAILED，TOOL_CALL_END 按 status，其余 OK）/ raw_object_id）。现有 AuditDenied 保留或收编均可，结果须一致。
- SSE：提交后 `PUBLISH sse:run:{run_id}`（键在 `rediskey` 加 `SSERun`）。EventSink 短事务提交后直接发；业务事务内的 AppendTx 由调用方提交后发（自己设计最小机制，如 `repository.InTxPublish` / 事务 after-commit 回调，写进汇报）。发布失败只告警。
- `internal/agent/harness/callbacks`（新包）：Eino 回调 handler，发 `STEP_STARTED / STEP_ENDED`（StepPayload，step_id 与 runner 的 SaveStep 一致）；`internal/agent/llm` 加调用钩子（Client 选项，如 `Observer func(ctx, LLMCall)`），callbacks 实现它：模型输入输出原文 `RawStore.Put(kind=LLM_IO)` 后发 `LLM_CALL_END`（RawObjectID 关联，payload 只含 token / 耗时 / 状态）。graph 侧补发 `RUN_STARTED`（RunStartedPayload，问题经 pii.Mask）、`KB_LOADED`、`ADVICE_READY`、`RUN_FAILED` / `RUN_INTERRUPTED`（runner 或 graph，选一处，避免重复）。图内事件全部经 `agent.EventSink`。harness 不得 import graph / repository（archtest）。改 graph / runner / llm 的地方尽量小，在汇报标明。
- `service.AuditService.ReadRaw(ctx, scope, runID, rawID)` + controller `GET /api/v1/farms/:farm_id/runs/:run_id/raw/:raw_id`：角色 farm_manager / agronomist / platform_admin；校验 raw_object 属于该 scope 且 run_id 一致；成功 → 5 分钟 MinIO 预签名 URL（minio-go `PresignedGetObject`，已在依赖里），审计 RAW_READ/OK 与签发同事务；拒绝 → 独立事务写 RAW_READ/DENIED，返回 403。
- 分区维护：`service` 内 `PartitionMaintainer`（`lock:scan:partition`，每月 25 日；按 Clock 判定），对 `audit_log`、`run_event` 执行 `REORGANIZE PARTITION pmax` 预建后两个月（已存在则跳过），`SELECT COUNT(*) ... PARTITION (pmax)` 非 0 告警；cmd/server 启动（可挂在现有 Scanner 周期里或独立 goroutine，退出时等待）。迁移账号与应用账号相同时直接执行，汇报说明。
