## 冻结的 HTTP 契约（A 实现，B 的页面按此调用）
- `GET /api/v1/farms/:farm_id/runs/:run_id/events`（SSE，`Last-Event-ID` 头或 `?last_event_id=`）：每条 `id: {seq}\nevent: {event_type}\ndata: {"seq","event_type","step_id","tool_call_id","actor_type","payload","created_at"}\n\n`；run 进入终态（RUN_COMPLETED / RUN_FAILED）或 RUN_INTERRUPTED 后发 `event: end` 并关闭；每 15s 发 `: ping` 注释保活。EventSource 无法带 Authorization 头，故同时接受 `?access_token=`（仅此路由，写进汇报）。
- `GET /api/v1/farms/:farm_id/approvals?status=OPEN`：在现有列表每项上加 `snapshot_digest`、`work_order`（`model.WorkOrder`，含 `constraint_checks[]`）、`awaiting_confirm`（HIGH 票已有第一人通过）、`first_approver`；只列 `ticket_kind=ORDER` 且 `OPEN`。
- run 详情 `execution.orders[].dispatch_result` 即 `DryRunDispatchResult`。
